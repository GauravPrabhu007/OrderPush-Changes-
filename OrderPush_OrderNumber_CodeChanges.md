# Code Changes Document: Add Optional "Order Number" Input to ZSCM_ORDERPUSH (Order Push Mode)

## 1. Overview

| Item | Detail |
|------|--------|
| **T-Code** | ZSCM_ORDERPUSH |
| **Program** | ZSCM_ORDER_PUSH |
| **Mode** | Order Push (rad1) |
| **Change** | New optional selection "Order Number" (multiple values). Filter SD FM output `lt_ex` by `ORDERNO` when the field is filled. |

---

## 2. Change 1: Selection Screen – New Input (Include ZSCM_ORDER_PUSH_SEL)

**Object:** Include **ZSCM_ORDER_PUSH_SEL**  
**Purpose:** Add optional, multi-value "Order Number" for Order Push (rad1). Use same block/visibility as other Order Push fields (MODIF ID p1 → visible only when rad1 is selected).

**Current code (block b1):**

```abap
SELECTION-SCREEN BEGIN OF BLOCK b1 WITH FRAME TITLE text-001.
SELECT-OPTIONS:  s_docno FOR vbeln MODIF ID p2,
                s_date FOR date MODIF ID p1,
                s_vkorg FOR vkorg MODIF ID p1,
                s_vtweg FOR vtweg MODIF ID p1,
                s_spart FOR spart MODIF ID p1.
SELECTION-SCREEN END OF BLOCK b1.
```

**New code:**

Add one SELECT-OPTIONS after `s_docno` (or after `s_spart`), **optional**, MODIF ID **p1** so it is shown only in Order Push (rad1):

```abap
SELECTION-SCREEN BEGIN OF BLOCK b1 WITH FRAME TITLE text-001.
SELECT-OPTIONS:  s_docno FOR vbeln MODIF ID p2,
                s_date FOR date MODIF ID p1,
                s_vkorg FOR vkorg MODIF ID p1,
                s_vtweg FOR vtweg MODIF ID p1,
                s_spart FOR spart MODIF ID p1,
                s_ordno  FOR vbeln MODIF ID p1.   " Order Number (optional, multiple) - Order Push only
SELECTION-SCREEN END OF BLOCK b1.
```

- **Naming:** `s_ordno` = new Order Number select-option (rename to your standard if needed, e.g. `s_ordno_push`).
- **Type:** `vbeln` is consistent with document number (SD/MM); if your `ZPTC_ORDER_DETAILS`-orderno uses another type (e.g. `vbeln_va`), use that type for the FOR clause.
- **Optional:** Do **not** add OBLIGATORY. No validation in AT SELECTION-SCREEN required when left empty.

---

## 3. Change 2: Pass Order Number to FM (Include ZSCM_ORDER_PUSH_FORM – Method `fetch_data`)

**Object:** Include **ZSCM_ORDER_PUSH_FORM**, method **fetch_data**  
**Purpose:** Pass the new selection `s_ordno` into `Z_SCM_GET_ORDER_DETAILS` so the FM can filter `lt_ex` by ORDERNO.

**Current FM call (in fetch_data):**

```abap
CALL FUNCTION 'Z_SCM_GET_ORDER_DETAILS'
  EXPORTING
    i_ord_date    = s_date
    it_vkorg      = lt_vkorg
    it_vtweg      = lt_vtweg
    it_spart      = lt_spart
  IMPORTING
    et_header_det = lt_header_det.
```

**New code:**

Add one exporting parameter (only for Order Push; when `s_ordno` is initial, FM will not filter):

```abap
CALL FUNCTION 'Z_SCM_GET_ORDER_DETAILS'
  EXPORTING
    i_ord_date    = s_date
    it_vkorg      = lt_vkorg
    it_vtweg      = lt_vtweg
    it_spart      = lt_spart
    it_orderno    = s_ordno    " Optional filter by order number(s) - filter on lt_ex after Z_PTC_OPENORDER_DETAILS
  IMPORTING
    et_header_det = lt_header_det.
```

- **Note:** `s_ordno` is the standard internal table + sign/option/low/high generated by SELECT-OPTIONS; type is RANGE of the FOR data element (e.g. `vbeln`). The FM must declare an import parameter with the same RANGE type (see Change 3).

---

## 4. Change 3: FM Interface and Filter on lt_ex (Function Module Z_SCM_GET_ORDER_DETAILS)

**Object:** Function module **Z_SCM_GET_ORDER_DETAILS**  
**Purpose:**  
- Add optional import parameter for order number(s).  
- After `Z_PTC_OPENORDER_DETAILS` fills `lt_ex`, filter `lt_ex` by `orderno` when the parameter is not initial.

### 4.1 FM Interface

Add one **importing** parameter:

| Parameter | Direction | Type | Optional |
|-----------|-----------|------|----------|
| IT_ORDERNO | Import | RANGE of document number (e.g. `RANGE OF vbeln_va` or type of `lw_ex-orderno` in ZPTC_ORDER_DETAILS) | Yes |

- In SE37, add parameter **IT_ORDERNO**, **Import**, **Optional**, type e.g. **RANGE OF vbeln_va** (or the data element used for orderno in `zptc_order_details_tt`).  
- If the structure uses a generic type (e.g. `vbeln`), use the same as in the program (e.g. `RANGE OF vbeln`).

### 4.2 Filter Logic Inside the FM

**Location:** Immediately after the call to `Z_PTC_OPENORDER_DETAILS` that fills `lt_ex`, and **before** the first use of `lt_ex` (e.g. before `LOOP AT lt_ex INTO lw_ex` for supplying_sloc/receiving_sloc checks).

**Current flow (conceptually):**

```abap
CALL FUNCTION 'Z_PTC_OPENORDER_DETAILS'
  EXPORTING
    vkorg  = it_vkorg
    vtweg  = it_vtweg
    spart  = it_spart
    date   = i_ord_date
    order  = abap_true
    sto    = abap_true
  IMPORTING
    ex_tab = lt_ex.

LOOP AT lt_ex INTO lw_ex.
  " validation...
```

**Insert after `ex_tab = lt_ex` and before `LOOP AT lt_ex`:**

```abap
  IMPORTING
    ex_tab = lt_ex.

" Optional filter by order number(s) - applied to SD FM output lt_ex (ORDERNO)
  IF it_orderno IS NOT INITIAL.
    DELETE lt_ex WHERE orderno NOT IN it_orderno.
  ENDIF.

LOOP AT lt_ex INTO lw_ex.
```

- **Behavior:** If the user does **not** enter Order Number, `it_orderno` is initial → no DELETE → all orders from `Z_PTC_OPENORDER_DETAILS` are processed. If the user enters one or more order numbers, only those orders remain in `lt_ex`; all downstream logic (validations, header/item build, `et_header_det`) then works on this filtered set.

## 5. Summary of Changes

| # | Object | Change |
|---|--------|--------|
| 1 | **ZSCM_ORDER_PUSH_SEL** | Add `SELECT-OPTIONS s_ordno FOR vbeln MODIF ID p1` in block b1 (optional, multiple; visible in Order Push only). |
| 2 | **ZSCM_ORDER_PUSH_FORM** (method `fetch_data`) | In `CALL FUNCTION 'Z_SCM_GET_ORDER_DETAILS'`, add `it_orderno = s_ordno` in EXPORTING. |
| 3 | **Z_SCM_GET_ORDER_DETAILS** | Add optional import `IT_ORDERNO` (RANGE of orderno type). After `Z_PTC_OPENORDER_DETAILS` → `lt_ex`, add: `IF it_orderno IS NOT INITIAL. DELETE lt_ex WHERE orderno NOT IN it_orderno. ENDIF.` |

---

## 6. Consistency Checks

- **AT SELECTION-SCREEN OUTPUT:** No change. `s_ordno` uses MODIF ID p1; when rad2 is on, p1 fields are already set inactive, so Order Number is hidden in Re-Push mode.
- **START-OF-SELECTION:** No change. Order Number is optional; existing mandatory checks for rad1 (date, vkorg, vtweg, spart) stay as they are.
- **Re-Push (rad2):** Uses `s_docno` and `s_date`; no use of `s_ordno`. No change required for rad2.

## 7. Text Element (Optional)

If you use a text symbol for the Order Number label instead of a hardcoded text:

- In SE38/SE80, Text elements for ZSCM_ORDER_PUSH: define a new text (e.g. 022) with text like "Order Number" and use it in the selection screen definition if your standard uses text-022 for select-options.

## 8. Type for IT_ORDERNO

- In the report, `s_ordno` is created by `SELECT-OPTIONS s_ordno FOR vbeln`, so its type is the standard RANGE table for `vbeln`.
- In the FM, use the same RANGE type as the domain/data element of `orderno` in the line type of `zptc_order_details_tt` (often `vbeln_va` or `vbeln`). If `orderno` is type `vbeln_va`, use **RANGE OF vbeln_va** for `IT_ORDERNO` so that `DELETE lt_ex WHERE orderno NOT IN it_orderno` is type-correct.
